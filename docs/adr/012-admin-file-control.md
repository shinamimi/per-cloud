# ADR-012 — 管理员文件管控：禁用机制 + 双回收站

> 日期: 2026-07-31
> 状态: 已接受

## 背景

管理后台文件管理需要管控用户文件（违规内容、超占空间等），需确定管控方式与删除边界。

## 决策一：禁用机制（新增）

| 维度 | 仅删除 | 禁用 + 删除 |
|------|--------|-----------|
| 管控力度 | 一刀切（文件消失） | 温和（可见但不可用） |
| 误判恢复 | 需从回收站恢复 | 一键启用 |
| 用户感知 | 文件没了 | 知道文件还在，但不能用 |

**决策：新增"禁用/启用"机制。** 禁用 = 用户仍可见文件，但**不可下载/预览/分享**；管理员可启用恢复。

**理由：** 禁用是比删除更温和的管控手段，适合"疑似违规待核查""暂不允许访问"场景，避免管理员误删造成不可逆影响；与删除形成两档管控梯度。

## 决策二：双回收站（按删除来源隔离）

| 维度 | 共用回收站 | 双回收站（按来源） |
|------|-----------|------------------|
| 可见性 | 管理员能看到用户自删的文件 | 全局(管理员删)与私有(用户删)隔离 |
| 恢复权 | 容易越权 | 按来源恢复，权限清晰 |
| 隐私 | 用户自删内容暴露给管理员 | 用户私有回收站管理员仅可强制清，不可见内容 |

**决策：两个独立回收站。**
- 管理员删 → **全局回收站**（仅管理员可见，可恢复/彻底删）
- 用户自删 → **用户私有回收站**（仅用户可见，用户可恢复）
- 管理员可删除用户的私有回收站内容（强制清理），但不可浏览其内容

**理由：** 管理员删除是"违规管控"，用户自删是"个人操作"，语义不同、隐私边界不同，隔离避免越权恢复和隐私暴露。

## 决策三：权限全部 ADMIN+

- 文件管理页（浏览/删除/禁用）全部 ADMIN+
- 前端路由守卫 + 后端校验双保险

**理由：** 跨用户文件操作是敏感能力，与角色矩阵中"ADMIN 有跨用户文件管理"一致；OPERATOR 无此权限。

## 影响

- FileStatus 新增 DISABLED；下载/预览/分享接口增加禁用校验
- t_recycle_bin 增加删除来源字段（ADMIN_DELETED / USER_DELETED）
- AdminFileController 全部 ADMIN+，前端路由守卫
- 管理员文件操作记 OperationLog
