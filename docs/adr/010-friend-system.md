# ADR-010 — 好友系统：双向确认 + 独立通用关系层

> 日期: 2026-07-31
> 状态: 已接受

## 背景

为支撑"团队拉人、定向分享"需要用户间的关系能力，需确定好友关系形态。

## 方案对比

| 维度 | 单向关注 | 双向确认 | 双向确认+拉黑 |
|------|---------|---------|--------------|
| 加好友成本 | 低（一键关注） | 中（等对方同意） | 中 |
| 关系可信度 | 低（可能不熟） | 高（双方同意） | 高 |
| 隐私骚扰 | 高（无需对方同意） | 低 | 最低（可拉黑） |
| 复杂度 | 低 | 中 | 中高 |

## 决策

**双向确认**：A 发请求 → B 接受才成为好友，有待处理请求列表。不引入拉黑（本期）。

- 关系独立表（t_friendship + t_friend_request），与团队（team_member）互不依赖
- 作为通用关系层：团队拉人、定向分享复用
- 定向分享对象：**好友 + 同团队成员**

## 理由

1. 双向确认关系可信，符合"好友"语义，避免单向关注带来的骚扰问题
2. 独立关系层与团队解耦，新增场景（定向分享、转存）直接复用，不需要团队参与
3. 本期不做拉黑，保持简单；如后续需要再扩展

## 影响

- 新增 t_friend_request、t_friendship 两表
- 定向分享接口需校验目标人与分享者的好友/同团队关系
