# ADR-001 — MinIO 存储结构：单 bucket + 前缀分区

> 日期: 2026-07-31
> 状态: 已接受

## 背景

文件模块需要确定 MinIO 对象存储的组织方式，涉及分片临时文件、个人文件、团队文件、缩略图、打包文件等多类对象。

## 方案对比

| 维度 | 单 bucket + 前缀分区 | 多 bucket |
|------|---------------------|-----------|
| 秒传 copyObject | 同桶内复制，实现最简单 | 跨桶复制需 CopySource 授权，实现复杂 |
| 管理成本 | 一个桶统一生命周期/配额/备份策略 | bucket 数量膨胀，管理分散 |
| 权限隔离 | 靠前缀规则区分 | 桶级天然隔离（如缩略图桶可公开读） |
| 生命周期策略 | 桶级统一 | 桶级独立（临时桶可自动过期） |
| 迁移成本 | 路径即归属，相对低 | 多桶迁移分散 |

## 决策

采用**单 bucket + 路径前缀分区**：

| 用途 | 路径 |
|------|------|
| 分片临时 | `uploads/{userId}/{uploadId}/chunk_{seq}` |
| 个人文件 | `files/{userId}/{fileId}/{objectName}` |
| 团队文件 | `files/team/{teamId}/{fileId}/{objectName}` |
| 缩略图 | `thumbnails/{userId}/{fileId}.jpg` |
| 打包 | `packages/{taskId}.zip` |

## 理由

1. 秒传（copyObject）是高频操作，单桶内复制无跨桶授权成本
2. 临时分片清理采用定时任务而非 bucket 生命周期策略，多桶的优势在本项目中无体现
3. 家庭/小规模部署场景，单桶统一管理更简单

## 影响

- 临时分片需定时任务清理（后续决策）
- 缩略图公开读需求不可通过桶级权限实现，统一走 presigned URL 或业务接口
