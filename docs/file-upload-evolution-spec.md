## 2. 文档A的目标、路径与视角

### 2.1 目标

用一个「自娱自乐级单机项目 → 企业级云盘」的文件存取链路演进故事，完整展示中级后端面试应答能力：

- 每阶段回答「怎么做的」「为什么这么做」「为什么不用 XXX」
- 让面试官对同一内容反复追问时，回答仍能自洽且不断深化
- 全篇读完后，读者能复述整条演进链路并应对任意一层追问

### 2.2 基本信息

| 项 | 值 |
|----|----|
| 文件路径 | `docs/notes/file-upload-evolution.md` |
| 标题建议 | 文件上传演进：从本机磁盘到对象存储（面试问答与技术手册） |
| 叙述视角 | **第三人称**（"候选人" / "面试官"），全文不得出现第一人称"我"作答 |
| 目标岗位 | 中级 Java 后端岗（K8s / MQ / 微服务仅按"口述层"口径回答，见 §8） |
| 篇幅 | 长篇完整实现，**正文 ≥ 20 页**（约 8000 字以上），每阶段含时序图与完整代码 |

### 2.3 文风：技术手册式问答（硬性要求）

问答只是**组织手段**，整体必须接近技术手册：

- ✅ 回答用精确术语、具体数据、结构化的定义（如"分片大小 5MB、并发 3"而非"分片大一点"）
- ✅ 对比一律用表格（维度 × 方案）
- ✅ 关键流程必须有时序图（Mermaid）与关键代码/配置片段
- ✅ 每个回答可以被独立阅读，不依赖对话上下文
- ❌ 禁止口语流水账、感叹词、无信息量的衔接语（"然后就是…""其实呢"）
- ❌ 禁止只给结论不给依据；每个"为什么"必须有代价/场景对比支撑

## 4. 六阶段定义表

| 阶段 | 标题 | 假设/真实 | 核心决策点（必须逐一回答"为什么"） |
|------|------|-----------|------------------------------------|
| 0 | 本机磁盘 + 后端转发 | **假设重构**（明确标注） | 存哪：本机目录（如 `/var/local/uploads`）；怎么传：单 POST multipart；怎么读：后端读文件流返回；为什么这样最简单，还能不能更差 |
| 1 | 代理到服务器 + 元数据入库 | **假设重构**（明确标注） | 引入服务器磁盘 + 数据库 `t_file` 表（id/name/path/size/md5/user_id）；Nginx 反代；为什么需要元数据；本机方案在真实部署下的崩溃点（丢文件、重启丢失、单点） |
| 2 | 分片上传 + 断点续传 | **假设重构**（明确标注） | 为什么单 POST 传大文件会失败；分片大小与并发度怎么定；接口形态（init/chunk/merge）；断点续传与进度（WebSocket）；分片临时对象怎么清理 |
| 3 | 秒传 + 引用计数 | **真实** | 参照 ADR-003：全站 SHA256 索引（`t_file_hash`）vs 仅本人 vs 无引用计数；为什么全站+引用计数；删除与回收站 30 天联动（计数归零才物理删）；团队文件复用同一机制 |
| 4 | 对象存储 MinIO + presigned URL 直连 | **真实** | 参照 ADR-001/002：磁盘 vs MinIO vs 云 OSS vs NAS；单 bucket+前缀分区 vs 多 bucket（秒传 copyObject 同桶复制的理由）；后端流式转发 vs presigned URL（10 分钟、302 重定向）；为什么 presigned 不占后端带宽 |
| 5 | 安全加固 | **真实** | JWT 鉴权 + 接口权限校验；presigned URL 时效（过期即失效）vs 每次实时校验；防遍历/越权（userId/fileId 归属校验）；回收站逻辑删除 + 引用计数物理删除联动；上传策略（单文件上限、并发数，VIP 差异化） |

真实阶段（3-5）的内容必须与仓库现状一致，见 §7。

## 5. 四轴必选对比清单

文档A必须覆盖「存 / 传 / 读 / 安」四轴。每轴至少包含以下对比（用表格，必须给出"为什么不用"的理由与适用场景）：

| 轴 | 必选对比 | 至少覆盖的维度 |
|----|----------|---------------|
| 存 | 本机磁盘 → 服务器磁盘 → MinIO → 云 OSS → NAS | 成本、运维复杂度、容量扩展、数据安全、迁移成本、单点风险 |
| 传 | 单 POST multipart → 分片(init/chunk/merge) → 秒传(SHA256+引用计数) | 失败重试、断点、大文件、重复文件命中、并发控制 |
| 读 | 后端流式转发 → presigned URL(302) → CDN | 后端带宽、权限时效、Range/断点、流量成本、访问日志 |
| 安 | JWT 接口校验 → presigned 时效 → 防盗链/签名 → 回收站+引用计数 | 越权防护、链接泄漏、删除一致性、管理成本 |

同一轴的对比必须**跨阶段递进**（如"存"轴在阶段0/1/4各出现一次且理由延续），不得在每个阶段各写各的。

## 6. 面试官追问要求（硬性量化）

- 每阶段 §X.4 至少 **5 条追问链**；每条链至少 **3 层**递进
- 递进方向示例：为什么不用 X → X 在什么场景反而更好 → 我们什么条件下会换 → 换的代价多大
- **对同一内容反复扩展**：每阶段至少 1 条链必须从表面问到部署/数据层（例：分片合并 → 合并失败一致性 → 临时对象回收 → 磁盘/对象碎片 → 存储生命周期策略）
- 追问链要包含「为什么不选真实方案的反方」（如阶段4 必须回答"presigned 为什么不做实时权限校验"）
- §8 扩展追问大合集：按面试官提问角度组织，每条都是可独立背诵的完整回答

## 7. 与仓库现状的强一致要求（阶段3-5）

文档A中标注「真实」的部分，**禁止编造**，必须与仓库可查证据一致，写前逐项核对：

| 事实项 | 核对来源 |
|--------|----------|
| 分片接口路径与流程：`POST /api/files/upload/init|chunk|merge`、`/upload/sec`、`/upload/policy` | `docs/file-module.md` + `backend/` 实际 Controller |
| 秒传方案：全站 SHA256 索引表 + 引用计数，删除"回收站到期 AND 引用计数=0" | `docs/adr/003-sec-upload.md` |
| MinIO 结构：单 bucket + 前缀分区（`uploads/{userId}/{uploadId}/chunk_{seq}`、`files/{userId}/{fileId}/{objectName}`、`files/team/{teamId}/{fileId}/{objectName}`、`thumbnails/…`、`packages/{taskId}.zip`） | `docs/adr/001-minio-bucket.md` |
| presigned URL：有效期 10 分钟、302 重定向、对象私有不公开读 | `docs/adr/002-presigned-url.md` + `backend/` 生成逻辑 |
| 下载/批量打包：下载重定向、打包异步 + WebSocket 进度 | `docs/file-module.md` |
| 回收站：逻辑删除 + 30 天物理清理 | `docs/file-module.md` |
| 技术栈实名：Java 21 / Spring Boot / MyBatis / Redis / MinIO / WebSocket / JWT；Vue3/TS；Docker Compose / Nginx；腾讯云轻量 2C2G | `docs/ARCHITECTURE-TECHNOLOGY-MAP.md` |

编写规则：

1. 涉及真实阶段的内容，先读上表来源文件再落笔
2. 时序图中的消息名、接口路径、参数名必须与代码一致；不一致时以代码为准并回改
3. 假设阶段（0-2）的接口可以自拟，但必须与真实阶段的演进逻辑衔接（如阶段2的分片接口形态是阶段4真实接口的前身，路径命名风格一致）
