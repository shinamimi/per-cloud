# 谷粒商城架构总结（学习笔记）

> 来源：尚硅谷《谷粒商城》全套视频课程（分布式基础 + 分布式高级 + 高可用集群）+ 公开学习资料整理。
> 定位：纯学习参考文档，总结外部项目的框架与架构，与本项目（自研云盘）无实现关联。

## 1. 项目定位

- **模式**：B2C 电商平台，平台自营商品销售给消费者（对标京东/天猫模式）。
- **组成**：前台商城系统 + 后台管理系统，前后端完全分离。
- **课程划分**：
  - 分布式基础（全栈开发篇）：SpringBoot + Vue + Element-UI + 逆向工程搭建后台管理系统。
  - 分布式高级（微服务架构篇）：SpringCloud + SpringCloud Alibaba 全套微服务治理方案。
  - 高可用集群（架构师提升篇）：Kubernetes + KubeSphere，集群化部署与 CI/CD。

## 2. 技术栈总览

| 层面 | 技术 | 用途 |
| --- | --- | --- |
| 后端框架 | SpringBoot、SpringCloud、SpringCloud Alibaba | 微服务基础框架 |
| 注册/配置中心 | Nacos | 服务注册发现 + 配置中心（替代 Eureka + Config） |
| 网关 | SpringCloud Gateway | 统一流量入口、路由、鉴权、限流 |
| 服务调用 | OpenFeign + Ribbon/LoadBalancer | 声明式远程调用 + 负载均衡 |
| 容错/限流 | Sentinel（+ Sentinel Dashboard） | 流量控制、熔断降级、系统自适应保护 |
| 分布式事务 | Seata（AT 模式，undo_log） | 跨服务事务一致；高并发场景改用可靠消息+最终一致性 |
| 链路追踪 | Sleuth + Zipkin | 全链路调用追踪 |
| 认证 | Spring Security + OAuth2、SpringSession | 登录态/权限、跨子域 Session 同步 |
| 缓存 | Redis + Spring Cache + Redisson | 缓存、分布式锁、分布式信号量 |
| 搜索 | ElasticSearch 7 | 商品全文检索 |
| 消息队列 | RabbitMQ | 异步解耦、延迟队列、柔性事务 |
| 数据库 | MySQL（分库分表 ShardingSphere） | 各微服务独立库 |
| 对象存储 | 阿里云 OSS / MinIO | 图片等静态资源 |
| 前端 | Vue + Element-UI | 管理后台 + 商城前台页面 |
| 部署 | Docker + Kubernetes + KubeSphere + Jenkins | 容器化、集群编排、CI/CD |
| 监控日志 | Prometheus + Grafana、ELK | 性能监控、日志收集分析 |

## 3. 微服务模块划分

### 3.1 后台管理系统（七模块）
系统管理、商品系统、优惠营销、库存系统、订单系统、用户系统、内容管理。

### 3.2 前台商城业务微服务群
| 微服务 | 职责 |
| --- | --- |
| 会员/认证服务 | 注册、登录、社交登录（微博/微信）、积分 |
| 商品服务 | 三级分类、品牌、属性（SPU/SKU）、商品管理 |
| 搜索服务 | ES 商品检索、聚合过滤 |
| 购物车服务 | 购物车管理（Redis） |
| 订单服务 | 下单、订单状态流转、取消 |
| 库存服务 | 库存锁定/解锁/扣减、采购、商品库存管理 |
| 支付服务 | 支付宝对接、支付回调 |
| 秒杀服务 | 秒杀专场、库存预热、快速扣减 |
| 优惠券/营销服务 | 优惠券发放与使用 |
| 仓储/物流服务 | 出库等（按需） |

> 设计原则：单一职责 + 独立部署，每个服务独立数据库。

## 4. 请求链路（典型）

```
用户 → Nginx（动静分离） → SpringCloud Gateway（路由/鉴权/限流）
  → 各业务微服务（Feign 互相调用）
  → MySQL（分库） / Redis（缓存/分布式锁） / ES（检索） / RabbitMQ（异步）
  → 第三方：OSS、支付宝
监控：Sleuth+Zipkin 链路 / Prometheus+Grafana 指标 / ELK 日志
```

## 5. 核心组件要点

### 5.1 网关（Gateway）
- 统一入口，动态路由（Nacos 配合）。
- 网关层做统一鉴权与限流，避免各服务各自处理。

### 5.2 服务调用（Feign + Ribbon）
- 声明式 REST 客户端，配合负载均衡。
- 所有跨服务调用必须配置熔断，防止服务级联故障。

### 5.3 容错限流（Sentinel）
- QPS 限流、熔断降级、系统自适应保护。
- 例：库存服务响应慢时商品详情页优雅降级。

### 5.4 认证与会话（SpringSession + Redis）
- 跨子域 Session 共享（单点登录到商城各子系统）。
- OAuth2 对接第三方社交登录。

### 5.5 缓存与分布式锁（Redis + Redisson）
- 缓存：Spring Cache 注解式缓存商品/分类等热点数据。
- 分布式锁：Redisson（下单、库存操作等防并发）。
- 分布式信号量：秒杀库存预热后快速扣减。

## 6. 关键业务链路

### 6.1 商品检索（ES）
- 商品服务同步/事件驱动更新 ES 索引。
- 检索：关键词 + 分类/品牌/属性过滤 + 聚合 + 排序分页。

### 6.2 下单 + 库存锁定（核心难点）
- 下单跨订单、库存、用户三个服务。
- **本地事务在分布式下的问题**：
  - 假失败：锁库存成功但返回超时，订单回滚、库存未回滚。
  - 部分回滚：锁库存成功、扣积分失败，无法回滚库存。
- **解决方案**：高并发场景不用 Seata AT（锁机制不适合高并发），改用**可靠消息 + 最终一致性**：
  - 订单本地回滚，库存服务订阅 `stock.release.stock.queue` 自动解锁。
  - 解锁场景：① 订单取消（手动/超时）② 后续业务失败导致订单回滚。

### 6.3 定时关单（RabbitMQ 延迟队列 + 死信）
- 订单创建 → `order.create.order` 路由进 `order.delay.queue`。
- 30 分钟未支付 → 消息过期成死信 → `order.release.order` 回到交换机 → `order.release.order.queue`。
- 释放订单服务监听该队列完成关单。

### 6.4 消息可靠性
- 三种丢失场景：网络未到 exchange、到 exchange 未入队宕机、消费未完成宕机。
- 对策：发送前记录消息到 DB + 定时扫描重发；生产者/消费者确认机制。

### 6.5 幂等
- 数据库唯一索引（订单号唯一约束防重复下单）。
- Redis Set 防重（MD5 去重）。
- 全局请求唯一 id。

### 6.6 秒杀
- 单独秒杀服务；秒杀链接加密（随机码机制）。
- 库存预热到 Redis 信号量，Redisson 分布式锁原子扣减。
- 秒杀队列削峰：抢到先响应，后台异步建单。

### 6.7 支付
- 支付宝对接，回调确认支付成功 → 触发订单状态流转、库存实际扣减。

## 7. 高可用集群（架构师提升篇）
- Kubernetes + KubeSphere 可视化编排。
- 集群化：Redis Cluster、MySQL 主从 + ShardingSphere 分库分表、RabbitMQ 镜像队列、ES 高可用集群。
- CI/CD：Jenkins 自动化构建部署。

## 8. 对外的学习价值 & 可讨论点
- **值得借鉴**：微服务按业务域划分、网关统一入口、延迟队列+死信实现定时关单、库存可靠消息最终一致、秒杀信号量削峰。
- **争议/演进点**（部分资料指出）：
  - RabbitMQ 可换 RocketMQ（原生支持事务/延迟消息/顺序消费）。
  - Seata AT 不适合高并发下单，需与 MQ 柔性事务搭配使用。
  - 团队规模小、并发不高的项目，微服务拆分价值有限——过度拆分引入运维与分布式事务复杂度。
